# 纯串流低延迟：第一阶段

0.2.0-zh.5 优先减少纯串流在绘制之后、提交之前的主动等待。生效条件为：Vulkan、直接帧映射、关闭垂直同步与时域帧混合、关闭 NR/VSR/应用内插帧，且没有使用延后交换线程。新帧到达后依靠已有事件调度尽快提交，不再在这条路径额外等待一个源帧间隔。

## 适用范围与回退

- 通过设置开启垂直同步、队列/帧混合或增强处理时，继续使用其原有呈现策略。
- Smooth Motion 是外部驱动处理；测试纯串流时也需在 NVIDIA App 中关闭，应用无法测量其实际状态和额外耗时。
- 启动前设置 `CHIAKI_LOW_LATENCY_PRESENT=0` 可恢复旧的提交节奏，便于同一二进制做 A/B 对照；省略该变量默认启用本阶段优化。变量在程序内首次渲染时读取，修改后需重启。
- IPC 保持 10；未改变网络协议、丢包等待、码率或解码器设置。

## 本机 A/B 验证

Windows、RTX 5070 Ti Laptop GPU、200 Hz 显示、1080p 合成输入。使用同一 Release 程序和隔离设置，分别恢复旧节奏与开启新策略；关闭所有增强、VSync 和详细逐帧日志。稳定输入各采样约 8 秒。

| 输入 | 旧：交付到提交 P50 / P95 | 新：交付到提交 P50 / P95 | 新：实际提交 FPS |
| --- | --- | --- | ---: |
| 30 FPS | 51.50 / 64.48 ms | 1.61 / 2.69 ms | 30.40 |
| 60 FPS | 23.99 / 32.03 ms | 1.32 / 2.09 ms | 58.80 |

“交付”指已准备显示的帧进入 `presentFrame`；“提交”指 CPU 从 libplacebo 交换链提交函数返回。它包含客户端待显示等待和基础渲染，不包含主机采集/编码、网络、视频解码、GPU 完成或屏幕扫描，**不是按键到屏幕延迟**。旧路径在选帧之后等待，其间下一张帧也可能在待显示槽中等待，所以交付到提交时间会大于单次 sleep。

30 FPS 诊断定时器以 33 ms 输入，因此可略高于 30；60 FPS 以 17 ms 输入，因此约为 58.8。实际输入数量单独统计，未将重复提交计为新帧。

±4 ms 的到帧抖动与 250 ms 的暂停注入检查通过：恢复后新帧无长队列积压；统计提交数约等于输入数。VSync、旧队列路径的 A/B 检查通过。AFG、DLSS FG 及 VSR/NR 组合另做实际渲染回归。结果只支持本机客户端调度改善，实际 PlayStation 串流节奏、撕裂和端到端延迟仍需验证。

## 可复用诊断

现有 `CHIAKI_RENDER_DIAGNOSTIC=plain` 渲染诊断增加以下参数，均只对诊断程序生效：

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `CHIAKI_RENDER_DIAGNOSTIC_WIDTH` / `_HEIGHT` | 1280 / 720 | 合成输入分辨率 |
| `CHIAKI_RENDER_DIAGNOSTIC_SECONDS` | 3 | 预热后采样 3–60 秒 |
| `CHIAKI_RENDER_DIAGNOSTIC_JITTER_MS` | 0 | 交替增减到帧间隔 |
| `CHIAKI_RENDER_DIAGNOSTIC_PAUSE_MS` | 0 | 大约两秒输入后模拟一次暂停 |
| `CHIAKI_RENDER_DIAGNOSTIC_VSYNC` | 0 | 设为 1，在诊断中真正开启 VSync；结果同时报告实际状态 |

`result.json` 新增交付到提交、选帧到提交和唯一帧提交间隔的分布，含 P50/P95/P99、均值和标准差；输入数与全部视频提交数单独记录。`presentation.csv` 保留各帧单调时间戳，支持复核。仅在诊断模式收集逐帧样本；旧队列或异步呈现没有对应直接帧样本时，统计对象为空，不伪造为零延迟。

下一阶段先结合真实串流观察画面节奏，再研究缺包情况下固定 16 ms 的等待。缩短乱序预算可能降低恢复率，应与 FEC、IDR 和 P95/P99 帧完成时间一起验证。
